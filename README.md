# JD 商品采集助手（浏览器扩展）

#仅用于个人学习与数据分析！！！
#For personal study and data analysis only！！！
在浏览器里直接采集京东商品详情和评论的 MV3 扩展。独立于仓库根目录的 Python 爬虫，
不修改、不依赖那份代码，只是复用了它的选择器、解析规则和限速参数。

## 它做什么

- 识别当前页面是不是京东商品详情页，并检测登录状态（读 cookie + 发真实请求二次确认）
- 点一个按钮，采集**当前打开的这个商品**的详情和评论，评论默认 10 条
- 采集结果显示在面板里，可导出合并 CSV（商品详情 + 评论两段）和完整 JSON
- 采评论时先点「全部评价」进入评论区，再在评论区范围内滚动加载
- 内置「检查页面结构」诊断，京东改版导致取不到数据时用来定位原因

只采集当前商品，不遍历搜索结果。这样访问量最小，也符合「看着哪个商品就采哪个」的用法。

## 安装

1. 打开 `chrome://extensions/`（Edge 是 `edge://extensions/`）
2. 打开右上角的「开发者模式」
3. 点「加载已解压的扩展程序」，选择本 `plugin_JD` 目录
4. 建议固定到工具栏，方便查看采集进度角标

## 使用

1. 正常登录京东（手动登录即可，扩展不需要你的账号密码）
2. 打开某个京东**商品详情页**（搜索结果页暂不支持）
3. 点扩展图标，确认「登录状态」显示已登录、「当前页面」识别为商品详情页
4. 设置评论数量，点「一键采集」
5. 采集期间可以关掉面板，进度会继续；重新打开面板即可看到最新状态
6. 完成后导出 CSV 或 JSON。CSV 里商品详情和评论分成两段，用「【】」标题隔开

采集**在你当前正在看的标签页里进行**，页面会自己跳转到待采集的商品，
方便你直接看到程序在做什么。采集结束后标签页停在最后访问的页面，不会被关闭。

采集顺序是：先用页面标题和中文标签提取商品字段，再点「全部评价」进入评论区，
然后在评论区范围内滚动加载评论。**不会把页面滚到最底部**，因为评论区下方
还有推荐位，滚过头就采集不到内容了。

如果发现某些字段取不到或评论为 0，点面板里的「检查页面结构」，
它会报告各类选择器在当前页面上的命中数量。把结果发出来就能定位到具体是哪一层变了。

## 结构

```
plugin_JD/
├── manifest.json          扩展清单（MV3）
├── background.js          Service Worker：登录检测、任务队列、导航调度
├── content.js             内容脚本：接收指令，在页面上读取和滚动
├── lib/
│   ├── selectors.js       京东页面选择器与限速参数（移植自 jd_config.py）
│   ├── utils.js           解析与工具函数（移植自 crawler/jd_utils.py）
│   └── crawler.js         商品提取与评论采集（移植自 crawler/ 下两个模块）
├── popup/                 弹出面板
├── icons/                 扩展图标
├── test/verify.js         离线校验脚本
└── 文件修改.md            本项目的修改记录（问题、原因、修改、验证）
```

## 与源项目的对应关系

| 本扩展 | 源项目 |
| --- | --- |
| `lib/selectors.js` | `jd_config.py` 的选择器列表与限速参数 |
| `lib/utils.js` | `crawler/jd_utils.py` |
| `lib/crawler.js` 商品部分 | `crawler/jd_product_extractor.py` |
| `lib/crawler.js` 评论部分 | `crawler/jd_comment_crawler.py` |
| `background.js` 登录检测 | `crawler/jd_browser.py` 的登录态探测 |

移植时保持了原来的尝试顺序和边界条件。比如销量解析的四条正则、
好评率的三种语序、评论「先清洗再计入配额」的计数方式，都和 Python 版一致。

## 验证

```bash
cd plugin_JD
node test/verify.js
```

这个脚本把 `lib/` 下的三个文件加载进 Node 的沙箱，用源项目
`tests/test_jd_utils.py` 里的同一批用例跑一遍，确认移植没有改变行为。
不启动浏览器，不访问京东。

## 设计取舍

**登录态检测分两步。** 先读 cookie 里的 `pt_key` 作为快速信号，再请求一次
`order.jd.com/center/list.action` 确认会话真的有效。只读 cookie 会把已过期的
会话误判成已登录，这一点在源项目里也踩过。

**任务状态放在 `chrome.storage.local`，不放内存。** MV3 的 Service Worker
空闲 30 秒就会被回收，进度写在内存里会直接丢失。导航之后也不靠 `sleep` 等待，
而是监听 `chrome.tabs.onUpdated`，这样 Worker 被回收后页面加载完成事件
还能把它唤醒继续跑。

**只做导航和滚动，不构造接口请求。** 评论的懒加载由页面自己发起请求，
签名也由页面生成，扩展不碰请求本身。这样既不需要处理 `h5st`、`thor`
这类签名参数，请求画像也和普通浏览器一致。

**读取用 DOM 而不是截图 OCR。** 内容脚本跑在隔离世界里，页面脚本看不到它，
读 DOM 本身不产生任何额外请求。OCR 相比 DOM 没有额外的隐蔽性，
却会带来准确率下降（`已售3万+87%好评` 这类文案识别错会直接污染统计）、
速度变慢，而且定位截图区域本身还是要读 DOM。

## 已知限制

- **评论依赖「全部评价」入口。** 采集前会点它进入评论区，再滚动加载。
  如果京东改版把这个入口去掉，或改成需要额外确认，评论会拿不到。
- **评论卡片的正文是按行抽取的。** 卡片里混着用户名、商品规格和正文，
  `extractCommentText` 按「丢掉用户名行和日期行，取最长一行」的规则提取。
  规则不对时会抽到规格文字，用「检查页面结构」里的 `sampleExtraction` 可以核对。
- **详情页的选择器是尽力而为。** 商品名称、价格、店铺在不同版式下可能取不到，
  取不到时沿用页面标题或留空，**不会用错值填充**。京东改版后需要同步更新
  `lib/selectors.js`。
- **不支持定时和后台自动运行。** 扩展只在用户点击时工作，这是有意的设计。

## 使用须知

这个扩展是给自己看数据用的工具，不是采集平台：

- 评论数量默认 10 条，面板里会显示一条红色提醒。**评论数量每增加一条，
  就要多滚一次评论区、多发一次请求**，全部记在你自己的登录账号上。
  超过 20 条时提醒会自动加重。实测大约每滚动一轮加载 3 条评论，
  所以 50 条约等于 17 轮滚动和 17 次请求。
- 遇到验证码或风控页面，扩展会直接报错停下，不会尝试绕过。
  按提示手动完成验证即可。
- 采集用的是你自己的登录账号。任何异常访问记录都挂在你的账号上，
  量越大风险越明显。
- 请遵守京东的服务条款。用于个人学习与数据分析是一回事，
  成规模采集需要先确认是否被允许。
